# Tracker: GitHub Issues

Slices, PRDs, and bugs for this game live as GitHub issues in **`CommanderFoxRocks/PushTheDoor`**.

**Issues only, not code.** GitHub here is an issue tracker, not the game's source of truth. The Luau code and instances live in the Roblox cloud experience and are edited through Studio MCP; do not commit game code to this repo. The repo holds only planning artifacts (`ROADMAP.md`, PRDs, slices, design briefs). `.gitignore` excludes local Studio/Rojo exports so they never get committed.

## Conventions

Use whichever route the session has:

| Action  | Local machine (`gh` CLI)                                         | Cloud session (GitHub connector tools)          |
| ------- | ---------------------------------------------------------------- | ----------------------------------------------- |
| Create  | `gh issue create --title "..." --body "..."` (heredoc for bodies) | `issue_write` (method `create`)                 |
| Read    | `gh issue view <number> --comments`                              | `issue_read` (issue + comments)                 |
| List    | `gh issue list --state open --label "..." --json number,title,labels` | `list_issues` (filter by labels/state)     |
| Comment | `gh issue comment <number> --body "..."`                         | `add_issue_comment`                             |
| Labels  | `gh issue edit <number> --add-label "..." / --remove-label "..."` | `issue_write` (method `update`, set `labels`)  |
| Close   | `gh issue close <number> --comment "..."`                        | `add_issue_comment`, then `issue_write` with `state: closed` and a `state_reason` |

- Prefix AI triage comments with `> *Generated by AI during triage.*`
- Label strings come from `triage-labels.md`.
- `gh` infers the repo from the clone; connector tools take `owner: CommanderFoxRocks`, `repo: PushTheDoor`.

## Keep ROADMAP.md too

Even with GitHub issues, maintain `ROADMAP.md` as the at-a-glance index, linking each line to its issue:

- `[ ]` not started
- `[~]` built and tested in Studio, awaiting human approval
- `[x]` built, playtested, and explicitly approved (append the approval date)

Studio-first devs read the roadmap more than the issue tracker.

## When a skill says "publish to the tracker"

Create a GitHub issue and add a linked checkbox line to `ROADMAP.md`.

## When a skill says "fetch the item"

Read the issue and its comments (`gh issue view <number> --comments`, or `issue_read`).
